# manymux for iOS

The Android app's iPhone and iPad twin: saved hosts, a machine's sessions as a
wall of screens or a list, and one of them on the screen to type in, scroll
back through, and hop away from. `android/README.md` says what each part does
and why; this app follows it.

## The parts

- The Rust core is the Android shim (`android/rust`), unchanged.
  `build-rust.sh` builds it as a static library for the device and the arm64
  simulator, generates the Swift bindings from that build, and wraps the lot
  in `build/ManymuxCore.xcframework`. Xcode runs it before every build.
- `Manymux/` is the app: SwiftUI for the screens, and a plain `UIView` for the
  terminal (`TerminalView.swift`), drawn from a display link for the reason
  the Android one is a plain `View`.
- `project.yml` is the Xcode project, generated by XcodeGen. The `.xcodeproj`
  and everything under `build/` is generated and not checked in.

## Building

```bash
brew install xcodegen
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
just ios-run        # build, install on the simulator, start it
just ios-test       # unit tests
```

Or `just ios-project` and open `ios/Manymux.xcodeproj`. For a device, put
`DEVELOPMENT_TEAM = <team id>` in `ios/Local.xcconfig`.

`ManymuxUITests` drives the app against a real machine and skips unless one is
named; its doc comment says how.

## What differs from Android

- There is no foreground service. iOS suspends an app shortly after it leaves
  the screen, the host stops hearing pings and detaches it, and the attach
  reconnects on its own when the app comes back. Nothing on the machine is
  lost; the half minute iOS allows on the way out covers a quick glance at
  another app.
- Paste is the system paste button, which reads the clipboard without asking
  every time.
- A hardware keyboard sends arrows, esc, tab and ctrl chords directly. There is
  no volume-key ctrl.
